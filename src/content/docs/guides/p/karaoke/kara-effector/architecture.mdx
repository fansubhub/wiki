## Arquitectura de Kara Effector

El sistema de Kara Effector no es una sola pieza, sino un conjunto de módulos interconectados. Mientras que `Effector-utils-lib-3.6` proporciona las herramientas de efectos, las siguientes librerías proporcionan la base sobre la que todo se construye.

### Librerías centrales del sistema

<Tabs>
<TabItem label="karaskel.lua">
:::note[Propósito]
Pre-procesamiento de datos de karaoke.
:::

Esta es la primera y más fundamental librería que actúa sobre los subtítulos. Su trabajo es analizar cada línea de diálogo temporizada y convertirla en una estructura de datos rica y fácil de usar. Es el "esqueleto" sobre el que los efectos construirán las animaciones.

- **Análisis de tiempos**: Parsea las etiquetas `\k` para obtener la duración y los tiempos de cada sílaba.
- **Manejo de _furigana_**: Detecta y separa el texto _furigana_ (texto sobre el _kanji_), calculando sus propias dimensiones y estilos.
- **Cálculo de dimensiones**: Utiliza las funciones de Aegisub para pre-calcular el ancho, alto y posición de cada sílaba y del texto completo en la pantalla.
- **Estructura de datos**: Organiza toda esta información en una tabla Lua (`line.kara`, `line.furi`) que se pasa a las funciones de efectos, simplificando enormemente el acceso a datos como `syl.width` o `syl.center`.

En resumen, `karaskel` hace todo el trabajo pesado de medición y posicionamiento inicial, para que los creadores de efectos puedan concentrarse en la animación.
</TabItem>

<TabItem label="Yutils.lua">
:::note[Propósito]
Biblioteca de utilidades avanzadas de bajo nivel.
:::

Esta es una librería externa extremadamente potente, creada por "Youka" (Christoph Spanknebel). El Kara Effector la utiliza como su motor para muchas de las operaciones más complejas y computacionalmente intensivas. Es una dependencia crítica que le da al KE gran parte de su poder.

- **Matemáticas avanzadas**: Incluye funciones para transformaciones matriciales 3D, cálculos de curvas Bézier, vectores y trigonometría.
- **Procesamiento de formas avanzado**: Contiene algoritmos muy optimizados para delinear (_to_outline_), aplanar (_flatten_), dividir (_split_) y detectar (_detect_) formas (_shapes_) vectoriales a partir de datos de píxeles.
- **Decodificación de archivos**: Puede leer y analizar archivos `.bmp` (imágenes) y `.wav` (audio), extrayendo datos que pueden usarse para crear efectos visuales.
- **Interacción con fuentes**: Puede obtener métricas detalladas de las fuentes del sistema y convertir texto directamente a formas vectoriales, una función crucial para efectos tipográficos.
- **Manejo de UTF-8**: Proporciona funciones robustas para trabajar con texto Unicode.

En esencia, `Yutils` es la "caja de herramientas de ingeniería" que permite a `Effector-utils-lib-3.6` ofrecer funciones de tan alto nivel.
</TabItem>

<TabItem label="utils.lua / utils-auto4.lua">
:::note[Propósito]
Compatibilidad y creación de atajos.
:::

Estos archivos no contienen mucha lógica original. Su función principal es actuar como "puente" o "adaptador". Cargan las librerías más modernas de Aegisub (como `aegisub.util` y `effector-auto4`) y crean versiones abreviadas o alias de sus funciones.

- **Atajos**: Definen funciones cortas como `R`, `Rs`, `Rd`, etc., que son en realidad llamadas a funciones más largas como `ke4.math.R`.
- **Alias**: Hacen que funciones de `aegisub.util` estén disponibles bajo nombres más antiguos o convenientes, como `table.copy`.

El propósito de estos archivos es hacer que el código de Kara Effector sea más limpio y fácil de leer para el autor, al tiempo que se aprovecha la potencia y eficiencia de las librerías estándar de **Automation 4** de Aegisub.
</TabItem>
</Tabs>

### Archivos de extensibilidad y configuración

<Tabs>
<TabItem label="Effector-newlib-3.6.lua">
:::note[Propósito]
Almacenar tus propias funciones y variables reutilizables.
:::

Este archivo está pensado para que los usuarios avanzados añadan sus propias funciones de utilidad, variables globales o formas personalizadas. Al mantener estas adiciones en un archivo separado, se evita modificar los archivos principales de Kara Effector. Esto tiene dos ventajas:

- Mantiene el código de Kara Effector limpio y original.
- Facilita la actualización de Kara Effector en el futuro, ya que puedes reemplazar los archivos principales sin perder tus personalizaciones.
</TabItem>

<TabItem label="Effector-newfx-3.6.txt">
:::note[Propósito]
Almacenar las configuraciones de los efectos que creas y guardas.
:::

Cuando creas un efecto en la interfaz de **Modify** y lo guardas, su configuración se escribe en este archivo. Cada entrada es una llamada a la función `effector.create_fx`, que define el nombre del efecto y todos sus parámetros. Este archivo actúa como una base de datos de tus presets de efectos, que Kara Effector carga cada vez que se inicia.
</TabItem>
</Tabs>

### Arquitectura general del sistema

Ahora que hes visto todas las piezas, el flujo de trabajo en Kara Effector puede ser resumido en:

<Steps>
1. **Inicio**

    El _script_ principal `Effector 3.6.lua` se ejecuta, carga todas las librerías (`karaskel`, `Effector-utils-lib-3.6`, etc.) y los archivos de configuración (`Effector-newfx-3.6`).

2. **Interfaz**

    Se muestra la interfaz gráfica al usuario para que seleccione las líneas, el tipo de efecto y la configuración.

3. **Pre-procesamiento**

    Al aplicar el efecto, `karaskel.lua` analiza las líneas seleccionadas y las convierte en estructuras de datos detalladas.

4. **Ejecución del efecto**

    La función del efecto seleccionado (definida a través de `effector.create_fx`) se ejecuta para cada sílaba/carácter/línea.

5. **Cálculos Internos**

    Durante la ejecución, la función del efecto utiliza las herramientas de las librerías:

    - Usa la librería `effector` para la lógica principal.
    - Usa las librerías `math`, `shape`, `text`, `color`, etc... de `Effector-utils-lib-3.6` para los cálculos.
    - Estas, a su vez, pueden usar las funciones de bajo nivel de `Yutils.lua` para las operaciones más complejas.

6. **Salida**

    El resultado final es un conjunto de etiquetas de **ASS**, generadas por la librería `tag`, que se insertan en nuevas líneas de subtítulo en Aegisub.
</Steps>

## Variables disponibles

En Kara Effector, las variables son atajos a propiedades de los elementos de karaoke (líneas, sílabas, etc.) y del entorno del script (resolución del video, etc.). Se pueden usar en casi todas las cajas de texto de la interfaz "Modify Effect", pero son más potentes en:

- `Return[fx]`: Para construir el texto o la forma final mediante un formato.
- `Variables[fx]`: Para definir valores personalizados que se usarán en otras cajas de texto.
- `Add Tags[fx]`: Para añadir efectos dinámicos basados en las propiedades del elemento.

#### Diferencias fundamentales entre variables de tiempo

Es muy importante entender la diferencia entre los tipos de variables de tiempo.

<Tabs>
<TabItem label="l.start_time">
:::note[Tiempo absoluto de la línea]
:::

| Descripción | Ejemplo |
| :--- | :--- |
| El tiempo de inicio de la línea de diálogo original, en milisegundos, desde el principio del video. Es un valor absoluto. | Si una línea empieza en la marca de 15 segundos del video, `l.start_time` será `15000`. |
</TabItem>

<TabItem label="syl.start_time">
:::note[Tiempo relativo a la línea]
:::

| Descripción | Ejemplo |
| :--- | :--- |
| El tiempo de inicio de la sílaba, en milisegundos, contado desde el principio de _su propia línea_ (`l.start_time`). Es un valor relativo a la línea actual. | Si la línea empieza en `15000` y la sílaba empieza medio segundo después, `syl.start_time` será `500`. Su tiempo absoluto es $15000 + 500 = 15500$. |
</TabItem>

<TabItem label="syl.syl_start">
:::note[Tiempo relativo al efecto]
:::

| Descripción | Función |
| :--- | :--- |
| El tiempo de inicio de la sílaba, en milisegundos, contado desde el principio de la **línea de efecto generada** (`fx.start_time`). | **Esta es la variable que casi siempre deberías usar dentro de una etiqueta [`\t()`](/aegisub/tags/advanced/transform)**. Un efecto (como una entrada anticipada o _lead-in_) podría empezar antes que la línea original, por lo que necesitas un tiempo relativo a la nueva línea de efecto. Se calcula como: (`l.start_time` + `syl.start_time`) - `fx.start_time`. |

| Ejemplo |
| :--- |
| La línea empieza en `15000` (`l.start_time`).
La sílaba empieza en `500` (`syl.start_time`). Tiempo absoluto: `15500`.
Tu efecto de entrada anticipada empieza en `14800` (`fx.start_time` - `200`).
`syl.syl_start` será $15500 - 14800 = 700$. Por lo tanto, `\t(700, ...)` se sincronizará perfectamente con la sílaba, pues le suma esos **200ms** de ventaja que le diste al efecto de _lead-in_ y no has tenido que calcularlo manualmente. |
</TabItem>
</Tabs>

#### Variables de efecto

Estas se llaman con `fx` y se calculan para cada línea de efecto que se genera. Son cruciales para entender el contexto temporal y espacial del propio efecto.

:::tip[Cajas de UI recomendadas]
`Return[fx]`, `Variables[fx]`, `Add Tags[fx]`.
:::

| Variable | Descripción |
| :--- | :--- |
| `fx.start_time` | El tiempo de inicio **real** de la línea de efecto que se está creando (en ms). |
| `fx.end_time` | El tiempo de fin **real** de la línea de efecto que se está creando (en ms). |
| `fx.dur` | La duración **real** de la línea de efecto (`fx.end_time` - `fx.start_time`). |

| `syl.syl_end` | Tiempo de fin de la sílaba **relativo al inicio del efecto**. |

#### Variables de bucle e iteración

Estas variables controlan los bucles para crear efectos complejos, repetitivos o por capas.

:::tip[Cajas de UI recomendadas]
`Return[fx]`, `Variables[fx]`, `Add Tags[fx]`.
:::

| Variable | Descripción |
| :--- | :--- |
| `j` | El contador del bucle principal (definido en la caja `loop`). Itera desde `1` hasta `maxj`. |
| `maxj` | El número total de iteraciones para el bucle principal. |
| `module` | **La variable más importante para la animación.** Representa el progreso del bucle `j`, normalizado de `0.0` a `1.0`.<br />Se calcula como $(j - 1) / (maxj - 1)$. |
| `module1` `module2` | Módulos de progreso anidados, relativos al número de sílabas y al número de líneas, respectivamente. |
| `J` | El contador del bucle externo (definido por la función `replay()`). |
| `maxJ` | El número total de repeticiones del efecto. |
| `moduler` | El progreso del bucle `J`, normalizado de `0.0` a `1.0`. |

### Aclaración sobre variables inaccesibles

Es tan importante saber lo que **no puedes** usar como lo que sí puedes. La inaccesibilidad de ciertas variables no es una limitación de Kara Effector, sino una consecuencia de cómo funcionan la programación y los "ámbitos" de las variables.

En resumen, solo puedes llamar a variables que existen y tienen un valor **en el momento exacto en que tu código en la caja de texto de la UI es evaluado**. Este momento es dentro de la función `effector.do_fx`, para una línea, sílaba e iteración de bucle específicas.

Aquí tienes una aclaración de las secciones y tipos de variables que **NO** puedes llamar directamente desde las cajas de texto de la UI de Kara Effector, y la razón.

#### Variables de configuración de la interfaz gráfica de usuario (GUI)

Estas variables definen la ventana que estás viendo. No son datos de karaoke, sino metadatos sobre la propia herramienta.

<Aside type="tip" title="Ejemplos" icon="list-format">
    - `effector.GUI_config`, `effector.GUI_modify`, `effector.GUI_karax`, `effector.GUI_shape`, `effector.GUI_trans`, `effector.GUI_add`, `effector.ipol_lines`.
    - Cualquier variable dentro de estas tablas, como `effector.GUI_modify[29].items`.
</Aside>

:::note[Razón de la Inaccesibilidad]
Estas variables se usan **antes** de que tu efecto se ejecute para construir el diálogo. Cuando escribes en la caja `Return[fx]`, la ventana ya existe. No puedes llamar a una variable que define la ventana desde dentro de esa misma ventana.
:::

#### Variables internas del motor del _script_

Estas son variables que el _script_ principal (`Kara Effector 3.6.lua`) usa para gestionar su estado, contar cosas y almacenar datos globalmente mientras se ejecuta.

<Aside type="tip" title="Ejemplos" icon="list-format">
    - `count_save`: Un contador para archivos de autoguardado.
    - `fx_box`: La tabla que contiene la configuración del efecto actualmente seleccionado para mostrarlo en la UI de **Modify**.
    - `list_fx, list_library`: Las tablas que contienen todos los efectos cargados, ordenados por categoría.
</Aside>

:::note[Razón de la Inaccesibilidad]
Son parte de la maquinaria interna y no son relevantes para el diseño de un efecto. Están fuera del **ámbito** de la función `effector.do_fx` que evalúa tu código. Permitir el acceso a ellas podría crear inestabilidad y resultados impredecibles. El _script_ solo te proporciona la información que necesitas para la tarea actual, como los datos de la línea (`l`) o la sílaba (`syl`).
:::

#### Variables locales y temporales de preprocesamiento

:::note[`karaskel.lua`]
:::

Antes de que tu efecto se ejecute, `karaskel.lua` analiza cada línea. Durante este proceso, usa muchas variables temporales para calcular anchos, posiciones y estructuras.

<Aside type="tip" title="Ejemplos" icon="list-format">
    - `worksyl`: Una tabla temporal que `karaskel` usa para agrupar sílabas con múltiples tiempos `\k`.
    - `cur_inline_fx`: Una variable que almacena el último efecto en línea (`\-`) encontrado.
    - `lgroups`: En la maquetación del furigana, es una tabla que agrupa sílabas para calcular su espaciado.
    - `toinsert`: Una cola de estilos de furigana que necesitan ser añadidos al archivo.
</Aside>

:::note[Razón de la Inaccesibilidad]
Son variables "locales" dentro de las funciones de `karaskel`. Una vez que una función termina su trabajo (p.e. calcular las posiciones de todas las sílabas en una línea), estas variables se destruyen y su memoria se libera. Recibes el **resultado final** de estos cálculos (p.e. `syl.width`, `syl.center`), pero no las variables intermedias usadas para llegar ahí.
<Aside type="tip" title="Analogía" icon="open-book">
    Es como pedir un plato en un restaurante. Recibes el plato terminado (`syl.width`), pero no tienes acceso a los ingredientes a medio cortar en la tabla del chef (`worksyl`).
</Aside>
:::

#### Variables internas de funciones de librerías

:::note[`Yutils.lua` `Effector-utils-lib-3.6.lua`]
:::

Puedes _llamar_ a las funciones de estas librerías (p.e. `shape.rotate(...)`), pero no puedes acceder a las variables que están _dentro_ de esas funciones.

<Aside type="tip" title="Ejemplos" icon="list-format">
    - Dentro de `Yutils.shape.split`, la tabla `new_shape` mientras se está construyendo.
    - Dentro de `shape.array`, las tablas `shape_radial`, `shape_rectangular`, etc., mientras se están generando.
    - Dentro de `effector.time`, las variables `Tim`, `Hor`, `Min`, `Seg`.
</Aside>

:::note[Razón de la Inaccesibilidad]
Este es un principio fundamental de la programación llamado "ámbito de función". Las variables declaradas dentro de una función solo existen mientras esa función se está ejecutando. Cuando la función te da un resultado (su `valor de retorno`), sus variables internas desaparecen.
:::

#### El objeto global `aegisub` y su estado interno

El _script_ interactúa con Aegisub a través de una API (Interfaz de Programación de Aplicaciones), que se compone principalmente de funciones. No expone su estado interno como variables que puedas leer.

<Aside type="tip" title="Ejemplos de lo que NO puedes hacer" icon="list-format">
    - `aegisub.selected_lines_count`: Una variable así no existe. Debes usar `aegisub.get_dialog_selection()`.
    - `aegisub.main_window_handle`: Punteros internos del programa.
    - `aegisub.undo_history_table`: La lista de acciones para deshacer.
</Aside>

:::note[Razón de la Inaccesibilidad]
Aegisub expone un conjunto controlado de **funciones** (`aegisub.text_extents`, `aegisub.progress.set`, etc.) por seguridad y estabilidad. No concede acceso directo a su memoria interna o al estado de la aplicación.
:::

### Resumen de variables inaccesibles

| Categoría | Variables/Secciones de Ejemplo | Razón de la Inaccesibilidad |
| :--- | :--- | :--- |
| **Configuración de UI** | `effector.GUI_config` `effector.GUI_modify` `fx_box` | Definen la interfaz gráfica; no son variables de datos de karaoke. |
| **Motor del _script_** | `count_save` `list_fx` `list_library` `fx_box` | Son parte de la maquinaria interna del _script_, fuera del ámbito de ejecución del efecto. |
| **Preprocesamiento** | `worksyl` `cur_inline_fx` (en `karaskel.lua`) | Son variables temporales y locales que se destruyen una vez que su tarea ha finalizado. |
| **Funciones de librería** | Variables internas de `Yutils.shape.split` o `tag.oscill` | Son locales a las funciones. Solo recibes el resultado final que la función retorna. |
| **Estado de Aegisub** | El número de líneas seleccionadas, el historial de deshacer | Aegisub no expone su estado interno como variables, solo a través de una API basada en funciones. |
